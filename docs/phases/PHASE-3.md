# Phase 3 executable contract — authenticated search, private profile and application ledger

**ISOLATED DEVELOPMENT.** The owner has authorized a four-PR development stack while P2-C remains in shadow. Private deployment is separately authorized. No auto-application or model-driven external action in this phase. Four sequential PRs P3-A–P3-D; keep legacy webhook alerts working if this private subsystem fails.

## P3-A: authenticated Discord interactions
- Verify official Discord Ed25519 signature and timestamp/replay controls before executing commands. Single owner's allowlisted Discord ID; private ephemeral replies and rate limiting.
- `/jobs find`, `/jobs top`, `/profile show`, `/github repos`, `/resume upload`, `/applications`, `/settings`, `/health`. Real buttons/commands: job source link, save, explain, request tailoring (only when Phase 4 live). No inert "Approve & Apply" before Phase 5.
- Defer tasks within Discord deadline, use durable queue for long analysis; sign all private URLs and reject cross-user/expired requests. No full channel scanning.

The isolated service emits the currently working command manifest with
`python -m jobbie_private.server commands`. Its `serve` mode binds to loopback and
`worker` processes deferred interactions through the original ephemeral reply.
`/tasks status` lists the owner's recent requests across restarts. Live
configuration requires `JOBBIE_DISCORD_PUBLIC_KEY`,
`JOBBIE_DISCORD_APPLICATION_ID`, `JOBBIE_DISCORD_OWNER_ID`,
`JOBBIE_PRIVATE_DB`, and a separately custodied Fernet `JOBBIE_PRIVATE_KEY`.
Use an existing owner-only directory outside Git, a supervised worker and an
owner-approved HTTPS ingress with body and connection time limits. Roll back
by removing the interactions endpoint and stopping both private processes.

## P3-B: durable private profile/storage and basic app ledger
- Owner-scoped private DB + private blob store for uploaded resumes, temporary PDFs, validated candidate answer drafts and job metadata. No raw resumes/citizenship details in public GitHub state or Discord embeds.
- Add immutable `JobSnapshot`, `ResumeVersion`, `Application` and `ApplicationAttempt` scaffolds with append-only events; `saved` is not `applied`. Versioning and owner-confirmed status changes only.
- Content-type/size checks, parser isolation, expiry/deletion, encrypted/scoped fetch links. Credential and auth integration are not assumed available; show exact setup blockers.

The isolated stack uses standard-library SQLite on an existing approved owner host. SQLite is public domain with no database service fee. Hardware, connectivity and HTTPS ingress availability are separate live gates. The parser accepts readable, unencrypted PDF and ordinary DOCX up to 5 MiB. An owner-only directory outside Git is required for the database and backups. A download uses `JOBBIE_PRIVATE_DOWNLOAD_TOKEN` in an Authorization header and a signed ticket generated by the local `resume-link` command. Use `resume-delete` for an exact version and `backup` for a fresh encrypted backup file. The owner console supports `profile-set` from stdin and explicit `application-open` and `application-status --owner-confirms`. [SQLite licensing and storage](https://www.sqlite.org/about.html) · [SQLite online backup](https://www.sqlite.org/backup.html)

## P3-C: verified facts / GitHub evidence
- Parse owner uploaded Epic/HCL/Tesla resumes; proposed facts require confirmation when new/ambiguous. No invented accomplishments, job titles, metrics, graduation dates.
- Public project evidence candidates (Clinical Notes synthetic demo, RegimeRadar real/demo distinction, Relay incomplete native, Drift no live capital). Attribution to user's actual code/PR, not simply README. Private repos allowlisted per repo, read-only, not automatically published or sent to model.
- Fact revocation invalidates derived match/resume recommendations. Keep source URLs/path/SHA and privacy scope.

The isolated service exposes `/resume propose` for an explicit uploaded version and `/github repos` for approved sources. The owner console supports `facts-propose`, `fact-inspect`, `fact-decide`, `github-approve`, `github-revoke`, and `github-propose`. Protected source text stays in the original private document during review. Repository approval takes JSON on stdin with the repository and author names, numeric IDs, visibility, and conservative stage. Use a fine-grained read-only `JOBBIE_GITHUB_READ_TOKEN` scoped to each approved private repository, with contents and deployments permissions only as needed. GitHub evidence is a proposal, and the linked author and signature fields describe what GitHub reports. Historical successful deployment evidence establishes the recorded deployment only. [GitHub commit evidence](https://docs.github.com/en/rest/commits/commits#get-a-commit) · [Deployment statuses](https://docs.github.com/en/rest/deployments/statuses#list-deployment-statuses)

## P3-D: transparent ranking, command search
- Hard eligibility tri-state remains authoritative. Starting weights role 30, verified skills 25, geography 15, salary 10, freshness 10, company 10; not a hiring probability. Unknown compensation is not zero.
- Explain `why match` / `what's missing` with candidate fact IDs and exact job source; avoid AI confabulation. Optional free-budgeted AI only for ambiguous explanations with privacy review; deterministic fallback works.
- Add actual saved-job statuses and feedback; nothing creates an employer submission or outbound email.

On an owner-approved host, provide `JOBBIE_P3_CATALOGUE_PATH` pointing at an owner-only, verified, standalone P2 schema-v2 SQLite snapshot outside the checkout. The reader checks each selected row's content digest and uses only read-only SQLite. It registers `/jobs find`, `/jobs top` and relevance feedback only when the snapshot is available at startup. View links to the original employer listing. Save records a private immutable reference. Explain rechecks current evidence and lists supported fact IDs and missing evidence. Results show earned points and available evidence weight. Source compensation needs explicit annual USD base pay to affect the $100,000 preference. Recorded posting evidence drives freshness. Excluded jobs stay hidden and review-required jobs appear without a score in search. Remove the snapshot setting and refresh the approved manifest to roll back the job commands.

The tests exercise 46 ranking scenarios from 23 preserved Workday and Microsoft Research postings, plus the 40 existing adversarial eligibility fixtures. The scenarios vary confirmed versus absent candidate facts. Further tests cover salary uncertainty, revocation, authenticated Discord controls and source database byte preservation.

### Phase 3 release gates
Authorized and unauthorized commands tested on signed interactions; file upload/deletion and private data isolation tested; 40 source-grounded ranking fixtures; app record idempotency, no false applied status; \$0 provider limits; old 13 network webhook not broken. Owner-facing live command only if account settings permit; otherwise exact BLOCKED_LIVE.
